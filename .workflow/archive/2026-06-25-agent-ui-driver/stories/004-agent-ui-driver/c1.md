**Non-blocking:** `xcodebuild test` runs under `set -euo pipefail` but its exit status is masked twice — by the `grep` filter (a non-matching grep would itself fail) and the trailing `|| true`. A test run that launches, writes `000-step.*`, then fails/crashes part-way through the script still passes the only gate (the artifact-existence check below sees `000-step.*` present) and the recipe reports success. Build/compile failures are still caught (no artifacts), so this is not a verdict blocker, but consider capturing `${PIPESTATUS[0]}` and surfacing a non-zero `xcodebuild` status so a genuinely failed run is distinguishable from a clean one.
