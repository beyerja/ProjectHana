**Non-blocking:** `resolveElement` matches on `label` first and only falls back to `identifier` when no label is given. A step that supplies *both* would silently ignore the (more precise, story-002) `identifier`. The committed scripts never set both, so there is no bug today — but since accessibility identifiers are the reliable matcher the feature added, consider preferring `identifier` when present, or at least documenting the label-wins precedence in the README so script authors aren't surprised.
