Non-blocking note: `home.mode.\(mode.quizModeRawValue)` is per-mode, so the same identifier (e.g. `home.mode.mapQuiz`, `home.mode.multipleChoice`) is rendered once per category section that includes the mode — up to 4 occurrences of the same id on one Home screen. This is intentional per the spec's naming-scheme reference ("the same mode under multiple categories shares one id, since the driver navigates by mode"), so it is not a defect. Flagging only so the driver/action scripts (stories 003/004) are aware that an exact-match `firstMatch` on `home.mode.<x>` resolves to the first matching category row and cannot distinguish category — which matches the documented "navigate by mode" contract.
