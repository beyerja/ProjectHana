**(non-blocking, out-of-scope robustness nit)** An explicit, sign-mismatched `velocity` is passed through verbatim. The default-velocity branch only sign-corrects when `velocity` is nil/zero; an explicit non-zero value bypasses it. So a contradictory step like `{"action":"pinch","scale":0.5,"velocity":2.0}` (zoom-out scale with a positive velocity) reaches `pinch(withScale:0.5, velocity:2.0)`, which `XCUIElement.pinch(withScale:velocity:)` rejects with `NSInvalidArgumentException` — aborting the run and subsequent artifact capture.

This does NOT block: the spec's "skip / no crash" guarantee is scoped to *unresolvable targets*, not malformed parameter pairs, and respecting an explicit velocity is the documented intent. Worth a follow-up: sign-correct (or skip) an explicit velocity whose sign contradicts `scale`, e.g. `velocity = (scale < 1) == (resolvedVelocity < 0) ? resolvedVelocity : -resolvedVelocity` (with the zero fallback as today).
