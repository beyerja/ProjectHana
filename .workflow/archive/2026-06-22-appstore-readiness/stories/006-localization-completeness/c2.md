**Non-blocking (design note):** the canonical key set is the UNION across all locales rather than the en base. Today `union == en` exactly, so there is no false failure — but the design is fragile: a stray/typo'd key added to only one locale (e.g. a misspelled key in nah, or an extra key only in es-MX) would join `canonical` and then be demanded of every required locale, failing the gate for the locales that correctly lack the typo and pointing the error at the wrong place.

Deriving `canonical` from the en base (the documented source of truth) would be more robust and self-consistent with `L10nCompletenessTests.swift`, which already drives its key list from the en bundle. Optional follow-up, not required for this PR.
