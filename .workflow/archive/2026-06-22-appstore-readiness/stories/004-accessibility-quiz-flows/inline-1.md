**Non-blocking (cleanup):** `isSelected(_:)` / `optionStateValue(for:)` here are a near-exact copy of `isSelected(_:in:)` / `optionStateValue(for:in:)` in `MultipleChoiceQuizView.swift`. Both switch over the same `MCQAnswerState` and return the same `a11y.state.*` strings; the only difference is whether the state comes from local `@State` or `session.answerState`.

Consider hoisting this onto `MCQAnswerState` (e.g. `func isSelected(_:) -> Bool` and `func stateValue(for:) -> String`) so the VoiceOver-state mapping lives next to the visual `buttonColor` mapping it must mirror. Today, a future `MCQAnswerState` case (or a swap of chosen/correct semantics) updated in one copy but not the other would make VoiceOver announce state correctly in one quiz mode and wrongly in the other — a divergence the new string test (key resolution only) would not catch. Cleanup-severity, not blocking.
