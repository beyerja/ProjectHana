# Story 001 — Add ko/nah locales, register bundles, and es-MX fallback chain

## Title
Add Korean and Nahuatl as selectable `AppLocale`s with the new-language → es-MX → English fallback.

## Goal
Make `.ko` and `.nah` first-class `AppLocale` cases that appear in the picker, persist, auto-detect
from device locale, and resolve UI strings and geographic names through the correct fallback chain.
After this story the app compiles, the picker shows "한국어" and "Nāhuatl", and selecting either
renders es-MX content where ko/nah data is absent (it will be absent until stories 002/003 fill it).

## Scope / changes
- `Hanahuac/L10n/AppLocale.swift`:
  - Add `case ko` and `case nah`.
  - `displayName`: `.ko` → "한국어", `.nah` → "Nāhuatl".
  - `matching(_:)`: map device language code `ko` → `.ko`; map Nahuatl codes (`nah`, and the common
    ISO `nhn`/other `nah`-collection variants if cheap to include) → `.nah`. Keep existing mappings
    (`es*` → `.esMX`, unrecognized → `.en`).
- `Hanahuac/L10n/L10n.swift` — `bundle(for:)`: for `.ko`/`.nah`, candidate chain becomes
  `[rawValue, "es-MX", "en"]` so a missing UI key falls through to Mexican Spanish, then English.
  Leave the existing 2-element `[rawValue, "en"]` chain for en/fr/de/es-MX unchanged.
- Models `Country`, `River`, `Sea`, `MountainRange` (`Hanahuac/Models/`):
  - Add optional `nameKo`/`nameNah` (and `Country.capitalKo`/`capitalNah`) decoded from
    `name_ko`/`name_nah` (and `capital_ko`/`capital_nah`). Until story 003 these will be nil.
  - `localizedName(for:)`: `.ko` → `nameKo ?? nameEs ?? name`; `.nah` → `nameNah ?? nameEs ?? name`.
  - `localizedCapital(for:)` (Country): analogous with capital fields.
- `Hanahuac/ko.lproj/Localizable.strings` and `Hanahuac/nah.lproj/Localizable.strings`: create the
  files (may be minimal — at least valid empty strings tables; full content lands in story 002).
- **Xcode project is generated by xcodegen** — do NOT hand-edit `Hanahuac.xcodeproj/project.pbxproj`.
  Instead add `- path: Hanahuac/ko.lproj` and `- path: Hanahuac/nah.lproj` to the sources list in
  `project.yml` (alongside the existing `*.lproj` entries, ~lines 24-27), then run `just generate` to
  regenerate the project. xcodegen will register the new regions/variant-group references. Verify the
  regenerated pbxproj includes `ko`/`nah` in `knownRegions` and the variant group.
- `LanguagePickerView` should automatically pick up the new cases via `AppLocale.allCases`; verify no
  hard-coded locale list needs editing.

## Acceptance criteria
- Project builds (`just build` / test scheme) with the two new cases.
- Picker lists "한국어" and "Nāhuatl"; selecting and relaunching restores the choice.
- `AppLocale.matching` returns `.ko` for a Korean locale and `.nah` for a `nah` locale.
- With ko/nah selected and no ko/nah data present, UI strings and geographic names render the es-MX
  value when one exists, else English — never a raw key, never blank.
- No regression for en/fr/de/es-MX (their fallback chains unchanged).
- Unit tests cover `matching` for the new codes, the `bundle(for:)` candidate chain for ko/nah, and
  `localizedName`/`localizedCapital` fallback (`nameKo`/`nameNah` nil → es-MX → en).
