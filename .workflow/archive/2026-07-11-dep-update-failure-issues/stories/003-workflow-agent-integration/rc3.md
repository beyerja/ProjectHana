**Non-blocking — stale-handoff gap.** If a `flake-lock-update` issue is open but the `automated/update-flake-lock` branch is missing or not ahead of main (e.g. already merged in a prior run), this state matches neither the no-handoff path ("**neither** a branch ahead of main **nor** an open issue") nor item 2 ("If the branch exists and is ahead"), so the instructions define no action and the rolling issue stays open silently. Consider: branch absent + issue open → close the issue as stale with a short comment (comment then close), and log it.
